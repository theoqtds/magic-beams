\section{Problem Resolution}

To start, in terms of data structures for our solution, we decided to use a two-dimensional array to store the positions of the beams. Moreover, we decided to use a graph implementation with adjacent lists (successors and predecessors).  In terms of algorithms, we decided to implement a BFS search to filter any unecessary nodes to the solution. Furthermore, Kahn's algorithm (topological sort) with built in acyclcity checking is used, so that disasters and beam removal order could be determined.

Firstly, we decided to incorporate a two dimensional array before beginning any operations with graphs or nodes. This was done so that beam dependancies could more easily and intuitively be made. The map is filled by iteration through every beam and filling the map based on the direction and length of the beam, filling up all coordinates that the beam belongs to with its integer ID.

After the map has been filled, we iterate through each beam, starting from where it ends and checking the tiles in that direction until the end of the map. For every unique number it passes a new edge is added to the graph corresponding to the dependancy it has on other beams. For the graph implementation itself, we decided to use an adjacent list both with sucessor and predessesor data structures as both inAdjacentNodes and outAdjacentNodes need to be performed on BFS and Topological Sorting. This decision makes both these operations more efficient temporaly.

Subsequently, now that we have the graph to work with, we can process the graph using Breadth First Search and Topological Sort to get our final answer. We use BFS to find the nodes that necessarily need to be processed (beams to remove) given the columns you want to clear. This is done by executing bfsExplore( ) on any unfound nodes that belong to the columns you want to clear.

Once BFS is executed, we have a boolean array holding information about the nodes found, with the index of the array associating to if the node of that id was processed by BFS. An int array is also generated that holds the ids of the nodes that were found, this is used to iterate through the Topological Sort algorithm.

After BFS is executed, the Topological Sort algorithm is executed to remove the beams in the right order. Since the problem states that whenever multiple beams can be freed, the one with the lowest identifier must be freed, a priority queue was used.

\section{Notation and Variable Definitions}

To analyze the complexity of the algorithm, the following letters represent specific quantities involved in the process:

\begin{itemize}
    \item \textbf{$R$}: The number of rows in the grid.
    \item \textbf{$C$}: The number of columns in the grid.
    \item \textbf{$B$}: The total number of beams provided in the input.
    \item \textbf{$K$}: The number of specific columns chosen to be cleared.
    \item \textbf{$D$}: The maximum dimension of the grid, defined as $\max(R, C)$.
    \item \textbf{$E$}: The number of graph edges created representing dependencies between beams.
    \item \textbf{$F$}: The number of beams that must be removed or reached by BFS ($F \le B$).
\end{itemize}

\section{Time Complexity}

\begin{itemize}
    \item \textbf{Setup and Mapping}: Allocating the grid map and marking cells occupied by beams takes $O(RC + B \cdot D)$.
    \item \textbf{Graph Construction}: Scanning from each beam's exit to find blockers takes $O(B \cdot D)$ plus $O(E)$ for edge insertions.
    \item \textbf{Target Search}: Scanning the $K$ chosen columns across $R$ rows and running a BFS through the graph takes $O(KR + F + E)$.
    \item \textbf{Topological Sort}: Removing $F$ beams using a PriorityQueue for ordered results takes $O(F \log F + E)$.
\end{itemize}

\textbf{Resulting Time Complexity}: 
\[ O(RC + B \cdot D + KR + F \log F + E) \]

\section{Space Complexity}

\begin{itemize}
    \item \textbf{Grid Storage}: The \texttt{beamIdMap} requires $O(RC)$ space to store the state of every cell.
    \item \textbf{Beam and Graph Records}: Storing $B$ beam objects and their $E$ dependency edges requires $O(B + E)$.
    \item \textbf{Auxiliary Arrays}: Arrays for tracking in-degrees and BFS visitation are bounded by $O(B)$.
\end{itemize}

\textbf{Resulting Space Complexity}: 
\[ O(RC + B + E) \]
In the worst-case scenario with a dense graph ($E = O(B^2)$), this simplifies to $O(RC + B^2)$.

\section{Conclusion}

  \subsection{Strengths}

  The solution has the following strengths:

  \begin{itemize}
      \item We used records such as \texttt{Beam}, \texttt{Answer}, and \texttt{FindRemove} to keep data representation
  simpler and to be able to pass several values throught the algorithms.
      \item The grid \texttt{beamIdMap} allows constant-time lookup of which beam occupies a given cell.
      \item Adding 1 to \texttt{beamId} before setting their position in beamIdMap, allows us to use the value 0 to identify the empty spaces. That way we dont have to set the whole array to (eg. -1) before inserting the beamIds. Before returning the result we subtract 1 from the beamId to return the correct value.
      \item The array \texttt{found} allows constant-time lookup of which beams have to be removed, by setting found[beamId] = true on the beams that must be removed
      \item The array \texttt{toRemove} allows ease of access of JUST the beams that have to be removed from the grid. It is used alongside with amountFound, so that we dont look further than we need in this array. 
      \item BFS is used to find only the beams that can affect the chosen columns.
      \item Kahn's algorithm is used to compute a valid removal order.
      \item Cycles are detected naturally: if not all required beams can be removed by the topological sort, the result is
  \texttt{Disaster}.
      \item We use a \texttt{PriorityQueue} correctly match the specification of removing beams in ascending order.
  \end{itemize}

  \subsection{Weaknesses}

  The main weakness of the solution is its memory usage. The algorithm allocates a full grid:

  \[
  \texttt{beamIdMap} \in O(R \cdot C)
  \]

  where $R$ is the number of rows and $C$ is the number of columns. This is efficient for direct access, but it can be
  expensive when the grid is large and sparse.

  Another weakness is the possible size of the graph. In the worst case, many beams can block many other beams, producing
  up to:

  \[
  E = O(B^2)
  \]

  edges, where $B$ is the number of beams.
